## 修改后的完整方案

内部知识问答试点实施计划（修订版）

一、 目标与定位
1. 核心目标：在明确数据与资源边界下，探测基于公开帮助文档的问答方式是否具备基础可用性，并收集当前查找方式的真实耗时基线。
2. 结论边界声明：本试点仅测量查询过程表现，不宣称整体员工效率改善，不预设任何财务或业务增长收益。试点结论仅代表特定问题集与特定员工，不可外推至全公司或其他业务场景。

二、 硬约束与安全边界（不可更改）
1. 数据源：只使用公开帮助文档，不得上传任何个人信息或客户资料。
2. 操作范围：只提出方案与对比，不操作任何业务系统。
3. 资源上限：最多投入两名员工各一天（按8小时/人计，共16工时）。一旦触及此时限，无论进度如何立即停止执行。
4. 可逆性：随时可回到原来的文档查找方式，无系统锁定。

三、 试点前准备（不计入两人一天的执行工时，由发起人提前完成）
1. 问题集抽取：从过去三个月IT支持工单、内部知识库搜索日志或新员工入职FAQ中，按出现频次提取排名前7的高频问题，以及3个文档未明确覆盖的边缘问题，共计10个问题。记录每个问题在公开文档中的可查性状态。若无法获取历史数据，则由不参与本次操作与评价的第三人（如部门主管）指定，并在报告中注明主观局限性。
2. 基线定义：明确‘当前查找方式’的标准操作流程（SOP），例如仅允许使用现有文档库搜索框和目录浏览，禁止询问同事或使用外部搜索引擎。
3. 计时口径书面化：固定计时起止点。起点为阅读完毕问题文本，终点为操作者确认找到答案且核对完文档出处。必须计入核对出处的时间。记录每次查询期间是否被中断。
4. 错误与停止标准定义：事先定义错误分类清单：(a) 答案与公开文档内容矛盾；(b) 答案在文档中找不到任何支撑段落；(c) 引用的段落与答案结论不一致；(d) 同一问题重复查询给出互相冲突且无文档支持的不同答案。‘缺少引用’定义为问答输出未提供指向公开文档具体段落的链接或路径。指定一名不参与操作的第三人作为最终判定人；若无第三人，则两名操作者独立判定，存在分歧时直接记为‘触发停止条件’。
5. 价值取舍原则确立：任何缺少有效文档引用或无法解释的答案，无论生成速度多快，均不计入有效效率改善，视为一次失败查询。

四、 执行步骤（在两人各一天的硬约束内进行）
1. 交叉设计分配：两名员工均需分别使用‘当前查找方式’和‘问答方式’解答相同的问题集。建议包含一名熟悉文档的老员工和一名相对陌生的新员工，以观察工具在不同熟练度下的表现差异。问题的测试顺序需随机或交叉排列，避免学习效应干扰。
2. 最低记录门槛：放弃‘必须完成10个问题’的数量执念。改为‘在每人一天的工时上限内，尽可能多地完成符合最低记录标准的问题’。每个问题的最低记录项必须包括：原始提问文本、两种方式的耗时（含中断标记）、问答输出原文、引用的文档出处链接、引用是否准确的判定结果。宁可只高质量完成5个问题，绝不为了凑数而跳过核对出处。
3. 安全阀触发机制：在执行过程中，一旦出现上述定义的(a)至(d)类错误或‘缺少引用’情况，立即停止该问题向更大范围的推广评估，但继续记录该次失败详情以供事后分析。触发停止条件不等于终止当天的其他问题测试，但意味着‘扩大试点’的选项被关闭。
4. 工时监控：每完成一个问题记录累计耗时。当单人累计投入达到8小时（一天）时，强制停止该员工的所有操作。

五、 评估指标与人工决策
1. 量化记录指标（非考核阈值，仅作观察）：(a) 具备完整且正确引用的前提下，平均耗时变化百分比；(b) 所有问答结果中，满足引用完整且可解释的比例。
2. 定性评估维度：试点结束后，由两名员工与发起人共同进行人工评估。评估的唯一决策依据是‘是否发现致命缺陷’（如高频出现幻觉、严重误导、停止条件未被有效触发等），而非寻找收益数字。
3. 后续决策：若未触发停止条件且记录完整，可考虑进入下一阶段（需另行设计更大样本的测量）；若触发停止条件或数据残缺，则维持现状，不再追加投入。

六、 商业逻辑说明
本试点本身不产生直接业务增长。其商业合理性在于：用极低的试错成本（两人各一天）验证一项潜在的效率工具是否安全可用。只有在本阶段证明‘答案准确且可追溯’后，释放的工时才具备被重新分配到客户交付等高价值任务的前提。若节省的时间未用于高价值任务，则不构成增长机会。

## 试点与验证计划

- 假设：在限定仅使用公开帮助文档的条件下，问答方式能在保证答案具备完整且正确引用的前提下，缩短单次查询耗时。
  - 方法：两名员工（一新一老）采用交叉设计，分别使用‘当前查找方式（按SOP）’和‘问答方式’解答相同的10个问题（7个高频+3个边缘）。书面固定计时起止点（含核对出处时间），记录每次查询的中断情况。任何缺少引用或不可解释的答案直接记为失败查询，不计入有效耗时比较。
  - 指标：1. 具备完整且正确引用的前提下，两种方式的有效平均耗时对比；2. 问答方式输出的引用完整且可解释比例（目标需达到较高水平才具备讨论效率的意义）。
  - 责任角色：试点发起人负责方案设计与时限监控；两名参与员工负责执行操作与原始记录；独立第三人（或双人交叉）负责错误与停止条件的最终判定。
  - 停止条件：1. 任一员工累计投入达到一天（8小时）即停止；2. 出现答案与文档矛盾、找不到支撑段落、引用指向错误等定义的‘错误’或‘缺少引用’情况，立即停止该方案向更大范围的扩大评估；3. 若时间压力导致无法满足最低记录门槛，主动缩减问题数量而非简化记录。

## 独立复核

修订方案在保留原硬约束（公开文档、不上传个人信息、不操作业务系统、最多两人各一天）的前提下，对问题选取偏差、计时口径、停止条件、工作量过载、价值取舍等核心设计缺陷进行了系统性修补。主要改进包括：引入客观问题抽样规则（7高频+3边缘）、交叉测试设计、书面化计时与错误判定标准、最低记录门槛、以及效率对准确性的绝对优先原则。修订将试点目标从不可验证的'效率验证'降级为'可用性探测与基线收集'，并明确限制结论不可外推。但仍存在若干未解决分歧：硬约束不可更改导致单日工时压力无法真正缓解；'不预设收益'与'增长机会'之间的逻辑张力未消除；部分修改（如问题来源依赖历史工单数据）在材料中仍属待验证假设。
